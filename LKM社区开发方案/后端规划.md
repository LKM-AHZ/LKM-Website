### 3.3 主键 / 时间戳 / 软删除 / 命名

| 约定 | 实况 |
|------|------|
| 主键 | **UUID**。PG 原生 `uuid` + 自建 `public.uuid_generate_v7()`（RFC 9562 uuid7，时间有序，`order_by(id) == order_by(created_at,id)`）。**例外**：`outbox_events.event_id` 保持 `String(36)`——它是 Pulsar Avro-record schema 契约，改类型会击穿事件链路 |
| 时间戳 | `TIMESTAMPTZ`，应用层统一 UTC（`UTCDateTime`） |
| 软删除 | `SoftDeleteMixin`（`deleted_at`），内容/评论域已铺开；回复树用 recursive CTE 级联 |
| 命名约定 | Alembic/PG 约束名前缀统一（`uq_` / `ix_` / `fk_`） |
| asyncio | 全部 `AsyncSession`，驱动 `asyncpg` |

### 3.4 Alembic 迁移

- **双链**：业务库 `alembic/versions/` 有 **2 条**——`0001_uuid_baseline`（全库基线，含 uuid7 函数、
  tsvector/trgm、hypertable）、`0002_optimistic_lock_version`；认证库 `alembic_auth/versions/` 有 **1 条**
  `0001_auth_baseline`。
- 命名采用 `NNNN_语义名`。**基线单文件建全库表**（一次性基线，属"每迁移只做一件事"的例外）。
- 运行期另有 `app/db/init_db.py` 的 `create_all` 通道 + `_sync_additive_schema` 加性同步（给已存在的表补列）。
- 大表破坏性变更走 `--sql` 离线评审 + 分批/`CONCURRENTLY` 口径（写入 DEPLOYMENT.md），**不做自动分批脚本**。

### 3.5 Repository 与连接池

- `app/db/repository.py` `AsyncRepository[ModelT]` 泛型基类：CRUD、动态软删、乐观锁 CAS、**只 flush 不 commit**。
- `app/db/repo.py` 提供模块级事务原语 `get_or_raise` / `consume_once` / `isolated_update`。
- **业务查询走 ORM/Repository**；全仓 `text()` 仅出现在探活（`health/router.py:151`）与索引谓词
  （`projects/models.py:85`），无裸 SQL 业务查询。
- 分层：多数模块 `router → service → repository`；`content/boards`、`content/qa` 等子包**无独立 repository**，
  service 直接查询（规则未机器强制，见 §8.2）。

**连接池（`app/core/config.py:63-78`、`app/db/session.py`）**：

| 池 | pool_size / max_overflow | 其他 |
|----|--------------------------|------|
| web（API） | 10 / 20 | `pool_recycle=1800s`、`pool_timeout=30s` |
| worker（后台） | 5 / 10 | 经 `new_worker_session`（`session.py:188`）独立池 |
| auth | 10 / 20 | |

> **仍只有 web / worker / auth 三种池**，「Web / Worker / Poller / APScheduler 各自独立池」未完全落地：
> APScheduler 本身不持 DB 连接（经总线触发），故未单列调度池。

### 3.6 TimescaleDB

- `outbox_events` / `outbox_archived` 转为 **hypertable**（按 `created_at` 时间分区），`outbox_archived`
  启用**原生压缩**（`add_compression_policy(..., INTERVAL '7 days')`）。
- 扩展缺失时（无 Timescale 的 PG）**降级为普通表**并 WARNING，不阻断启动。
- **PG「连续聚合视图」已落地**：`points_ledger`（hypertable）+ `points_daily`（日桶 × `reason`
  即行为类型），由 `app/db/init_db.py::_ensure_continuous_aggregates` 与迁移 `0004` **双通道**
  装配（改一处须同步另一处）；唯一读口 `/admin/points-report`（离线面，非 TimescaleDB 实例返
  503）。内容/用户增长类指标**不在覆盖内**——源表被 FK 引用，转不了 hypertable。

## 四、认证、鉴权与安全（AUTH 微服务）

### 4.1 边界与公开面

- `auth/` 顶层包 53 个 `.py` + `db/` + `providers/`；`auth/main.py:90-103` 独立装配全部 router。
- **app 侧只能经 6 个公开面引用 auth**：`auth` / `auth.deps` / `auth.schemas` / `auth.snapshot` /
  `auth.seams` / `auth.entities`（白名单见 `pyproject.toml:229-279`；其余 40+ 内部模块对 `app` 禁入）。
- auth **不反向依赖** app 业务面（`app.modules/app.api/app.ws/app.flows/app.main`），
  仅 4 处经 `ignore_imports` 豁免（共享 storage 抽象 + 两个 flow 纯体层，均惰性调用）。

### 4.2 JWT + Refresh Token

| 项 | 实况 |
|----|------|
| 签名算法 | **双模**：默认 `HS256`（`config.py:84`）；配了 RSA 私钥即 **RS256**（`auth/jwt_keys.py:92-96`）。生产配私钥后**装配期强制关闭 HS 回落**（`config.py:539-543`） |
| HS 回落 | `jwt_hs_fallback` 默认 True；`decode` 放行 HS256（`jwt_keys.py:158-161`），带生产护栏 |
| 有效期 | access 15min、refresh 7 天、admin cookie 15min（`config.py:107-111`） |
| 轮换 | `refresh_access_token` 用 `consume_once` 原子撤销旧 token 再发新对；DB 只存 SHA-256 哈希（`auth/service_auth.py:82,655-694`） |
| JWKS | `/.well-known/jwks.json`（`auth/router_jwks.py:21-24`），RFC7638 `kid` |
| 验签公钥就绪 | `verification_status()`（`jwt_keys.py:249-261`）+ 运行期 JWKS 拉取（`:264-295`）；readiness 有 `verify_key` 硬依赖项 |
| audience 隔离 | `lkm:web` / `lkm:temp` / `lkm:admin`（`auth/security.py:60-61`、`auth/admin_session.py:36`） |
| 算法混淆防护 | decode 按头部 alg 分支、每支单算法白名单 |

### 4.3 密码与会话安全

- 口令哈希：`argon2.PasswordHasher`（Argon2id），内建 salt；用**虚拟哈希**防用户名枚举（`auth/security.py:22-51`）。
- 会话：refresh token 落 DB `refresh_tokens`（权威）；撤销预检走 Redis。
- **撤销**：`token_version`（DB 比对）+ `jti:block:{jti}` / `tv:min:{user_id}` 预检缓存
  （`auth/token_revocation.py`，TTL 带抖动），**缓存只用于加速拒绝、绝不据此放行**，DB/seam 为最终判据。
- 多设备撤销 `revoke_all_refresh_tokens`（`service_auth.py:697`）；admin 登出按 jti 即时失效。
- 登录限流 + 失败锁定（`auth/limits.py`、`locked_until`/`failed_login_attempts`）。
- CSRF：仅 **admin cookie** 有 `samesite="lax"`；前台 refresh 以 JSON/header 返回，**不落 HttpOnly cookie**。

### 4.4 RBAC 权限模型（**与旧版蓝图差异最大处**）

- **RBAC 不在 AUTH 包内**，而在业务侧 `app/modules/rbac/`（`service.py`/`deps.py`/`permissions.py`/`seed.py`）；
  AUTH 仅 `service_authz.py` 做会话裁决与升权。
- **无** `user / group / role / permission` 四表；只有一张 `role_permissions`（`app/modules/admin/models.py:54-64`）。
- 角色是**复合角色** `{account_level}:{profile.role}`：`local|normal|admin` ×
  `member|columnist|author|incubated_member|org_member|super_admin`（`rbac/permissions.py:78-216`），
  **没有** root/admin/moderator/member 那一套。
- 判定入口是 `require_permission` / `get_current_admin` / `role_has_permission`（**无** `require_roles("admin")` 字面）。

### 4.5 中间件与防护

`install_security_middleware`（`app/core/middleware.py:238-268`）装配 **4 件**：

1. **TrustedHost**（生产禁 `*`）。
2. **CORS**——**仅非生产**在应用层挂；生产 CORS 权威在 APISIX。
3. **SecurityHeaders**：`nosniff`、CSP `frame-ancestors 'none'`、`X-Frame-Options: DENY`、Referrer-Policy、
   Permissions-Policy；HSTS **仅生产**。
4. **RequestId**：写 ContextVar + 回写 `X-Request-ID` + 进 JSON 日志。

另：`GraphQLHTTPMiddleware`（硬超时，见 §6）。**无全局限流中间件**——限流在 APISIX + 端点级 `check_code_rate_limit`。

### 4.6 密钥管理

- **Infisical** 已接入：`app/core/secrets_bootstrap.py`（universal-auth machine identity，支持 `_FILE` 引导），
  `deploy/docker-entrypoint.sh` 启动前拉取。**Vault 不存在**。
- **口径**：**既有环境变量优先，Infisical 只补缺**；未启用时 fail-open 回落 `.env`。故非"零明文"终点。

## 五、消息驱动：Pulsar 统一总线

### 5.0 抽象层与命名空间

- `app/core/messaging.py` 暴露 `publish(routing_key, payload)` 与 `run_subscription(name, handler)`；
  订阅名走 `SUBSCRIPTIONS` 注册表，业务按 `routing_key` 发布（**拿不到直接指名 topic 的入口**）。
- **命名空间白名单** `NAMESPACES = {auth, biz, system}`；`_topic()` 对未知命名空间 import 期即抛错。
- `_validate_namespace_isolation()`（`messaging.py:105`）在 **import 期**校验「订阅声明的 routing_key
  必须与其 topic 同命名空间」——**命名空间隔离由消息层强制**。
- **单一 broker**：只有 Pulsar（`Transport` Protocol 仅为 publish 的测试 seam）；无 Rabbit/QoS 双后端。

### 5.1 事务发件箱

| 组件 | 实况 |
|------|------|
| 入队 | `app/db/outbox.py` `enqueue_outbox`（同事务入队）；`event_id` 幂等为**先查后插 best-effort** + 唯一约束 `(event_id, created_at)` |
| relay | `app/core/outbox_relay.py` `relay_poll`：`FOR UPDATE SKIP LOCKED` 领取、认领即写锁并 commit、陈旧锁超 `outbox_lock_ttl_s` 重领 |
| leader 选举 | **Redis 租约**（`SET NX EX` + 原子续约），`worker_outbox` 为入口；指标 `outbox_leader_total{acquired,contended,renew_failed,stale_reclaimed}`、`outbox_pending_count` |
| 重试 | `MAX_TRIES=5`，指数退避 cap 1h；达上限**直接删 outbox 行并迁 `event_failures`**（outbox **无 `status=failed` 行**） |
| 归档 | `archive_published` 先写 `outbox_archived` 再删 |
| 人工重放 | `app/db/event_failure.replay_failure` + `app/modules/admin/event_failure_router.py`：`GET /admin/event-failures`、`POST /{id}/replay`（**沿用原 event_id 重入 outbox**，走发件箱而非直投；总线未启用时返 503 且不删归档行） |
| 幂等 | `app/db/event_processed.py`（`scope,event_id` 复合主键）+ `worker.py:_dispatch_with_dedup`（best-effort） |

### 5.2 topic 全集（`messaging.py:128-138`）

| topic | 用途 | 订阅/消费者 |
|-------|------|-------------|
| `persistent://lkm/auth/email` | 验证码 / 欢迎 / magic link | `worker-send` |
| `persistent://lkm/auth/user.events` | 用户变更/封禁/会话撤销 | `worker`（user-invalidate） |
| `persistent://lkm/auth/audit.login_fail` | 登录失败审计 | `worker`（audit） |

### 5.3 消费者语义与死信

- 手动 ack：成功 ack，异常/超时 negative_ack 重投（`messaging.py:519`）。
- 死信：`ConsumerDeadLetterPolicy` → `system/dlq`；`worker_dlq` 落 `dlq_messages`，admin `requeue` 人工重投。
- **无 TTL 自动重试**（仅按 redelivery 次数死信）。

### 5.4 跨 AUTH 读模型

- **在线读 = `user:snap` 缓存 + AUTH 只读 API 回退**：
  - `app/core/user_cache.py`：`user:snap:{id}` 键，L1+L2 两级，**版本 CAS**（`sv`）防 LWW，**epoch 墓碑**防复活，
    **负值缓存**防穿透（`_NEG_TTL_S=30`，`write_negative`）。
  - AUTH 只读面：`auth/snapshot.py`（读路径）、`auth/user_http.py:163`（进程内 HTTP）、
    AUTH 端点 `GET /api/v1/auth/internal/users/by-ids`（`auth/router_read.py:119`，批量、分块、单次上限常量）。
- **变更即失效**：AUTH 发 `user.updated`/`banned`/`session_revoke` → 主服务消费**仅失效 `user:snap`**
  （`auth/tasks.py:58-72` `invalidate_user_snap`，注册点在 `:227`），**不写缓存值**；跨实例 L1 失效经
  `app/core/user_cache_events.py` 的 `cache:l1:invalidate` 广播（**只删 L1，不 DEL L2**）。
- **`user_dim` 报表宽表**：`app/db/user_dim.py` 表 + `app/flows/user_dim.py`（Prefect flow：增量/ids 回填/对账）
  + `auth/user_dim_sync.py`；**只读副本、只服务运营报表/后台列表**，在线读绝不读它。
  `auth/tasks.py` 在 `user.*` 失效路径上**同时** `refresh_user_dim_event`——**已回审并保留**（Profile-only
  变更不 bump `users.updated_at`，纯周期谓词看不见它；且为幂等 upsert 而非失效）。
- **种子数据**：demo 用户经 `auth/seams.ensure_demo_user`（auth 库会话 upsert 的不可登录用户）创建，
  业务侧只取回裸 uuid——业务库路径**不出现任何 auth 表写**。

### 5.6 缓存策略

- **L1**（`local_cache.py`，有界 TTL+LRU，仅加速）+ **L2**（Redis）。
- `app/core/cache.py`：`jitter_ttl()` TTL 随机扰动（**L1 只向下扰动**；`jti:block`/`tv:min` 等"TTL 是上界"
  的预检缓存亦纳入）、`cached_read()` singleflight + L2 锁 double-check。
- `app/core/cache_lock.py`（L2 互斥锁）、`app/core/singleflight.py`（引用计数回收）。
- **布隆过滤器（`user:snap` id 白名单）**：位图 = 全部合法 user id，落 **Redis bitmap**（跨进程可见）。
  `bloom.definitely_absent(key)` 为真 ⇒ 该 id 从未存在 ⇒ 短路，不打上游。拦截点在
  `user_cache.read_snap_state` / `read_snaps_state` 的 **miss 分支**与 `auth/snapshot.py`
  `_retrieve_fields_batch` 入口（**命中路径不查布隆**，热路径零额外往返）。
  - 完整性靠三处：**全量预热**（`auth/bloom_seed.backfill_user_ids`，cron 每日 03:50 + auth 进程启动后台跑）、
    **建号即 add**（`auth.service_auth.create_user_with_profile` 等）、**只增不重建**（布隆不可删，但已删
    用户的 id 留位图里无害——会落回真实查找由负值缓存兜）。
  - **门禁**：只有 `mark_seeded()` 打过「已预热」标记（带 TTL）才允许拒绝；未预热/标记过期/Redis 不可用/
    命令异常一律**不拦**（fail-open）。`write_negative` **不再**写布隆（那是反语义）。
  - 覆盖场景：客户端可控 key 的读路径，如 `POST /api/v1/users/{user_id}/follow` 传任意 uuid。
- 计数：写路径与明细**同事务改计数列**（写穿，`LKM_COUNTERS_WRITE_THROUGH` 默认 true）；Redis write-behind
  退为回退通道；对账按 `counts_reconciled_at IS NULL` 增量扫 + 日级全量兜底 `reconcile_content_counts_full`(04:00)，
  震荡只告警不自动暂停。

### 5.7 WebSocket

- `app/ws/{broker,manager,router}.py`，路由 `/ws/events`；基于 L2 pub/sub（`ws:*` psubscribe），
  频道白名单 `upload` / `notification`，`ConnectionManager` 按 `user→channel`，heartbeat ping/pong + refresh token。
- 推送内容 JSON + version/event_id，客户端幂等去重；**只推送，不做业务写入**。

## 七、工程实践

### 7.1 错误处理协定

- 统一信封 `ApiResp{code, message, data, request_id}`（`app/core/common.py:10-21`）——字段是 **`message`**
  （**非** `msg`；前端 `http/client.ts` 侧双名兼容），`request_id` 与 `X-Request-ID`、结构化日志同源。
- 异常基类 `BizError`（`app/core/err.py:155`）+ `CommonErr`/`AuthErr`；错误码 `ns<<16|local` 命名空间编码。
- 唯一冲突统一 **409**（`EMAIL_TAKEN`/`DUPLICATE_LIKE`…；中性兜底 `CommonErr.CONFLICT`），非 400。
- **无裸 `HTTPException`**（仅注释提及）——git smart-HTTP、`/auth/internal/*`、bot-sso 全走统一 handler
  （`BizError` 可携带响应头，git 的 `WWW-Authenticate` 原样保留）。
- 422 由 `RequestValidationError` 映射；429/503 自动补 `Retry-After`；永久失败入 `event_failures`。

| 维度 | 实况 |

| 跨进程取数 | `metrics_relay`：非 API 进程按 `metrics_relay_interval_s`（默认 15s，对齐抓取间隔）把本进程指标快照写进 `lkm:{env}:metrics:relay\|{实例}`（TTL=3×周期，进程没了键自然过期），backend 进程扫描该前缀后聚合——**counter 记远端增量**（远端回退只重置基线、绝不让本地计数回退：既避开 `Counter.inc(负数)`，也让 Prometheus 侧不出现 counter reset）、**gauge 取跨实例 max**（非 leader 副本的 0/陈旧值不得拉低积压读数）。与 `scheduler_state`（调度器运行态）同范式。取舍：远端 counter 是「本地 + 增量」的近似，**斜率正确但不适合当绝对总量做账**；gauge 取 max 只对「越大越坏」的量成立 |
| 抓取与告警 | `deploy/prometheus/prometheus.yml` **只抓 `backend:8000`**；规则 4 文件（`lkm-outbox`/`lkm-audit`/`lkm-pool`/`lkm-metrics-relay`），k8s `kustomization.yaml` 逐条列全（防回归测试 `tests/deploy/test_prometheus_config.py`）。`lkm-metrics-relay.yml` 守的是**中继链路自身**（`metrics_relay_up == 0` 持续 10 分钟即告警），免得"指标静默冻结在旧值"再把假保护挪一层 |

### 7.4 部署与工程化

- Dockerfile 多阶段；运行时 `uvicorn --workers ${LKM_WEB_WORKERS}`（**未用 gunicorn**）。
- k8s 探针：backend/auth 均 **startup + readiness + liveness 三级**（`/api/v1/{liveness,readiness}`）；
  **worker 无探针**（`workers.yaml` 明示）；frontend 无 startup。
- CI（`.github/workflows/ci.yml`）job：`lint`（ruff + import-linter + 裸 SQL 检查）、`typecheck`（ty，**非阻断**）、
  `migrations`、`test`（pytest + 真 PG）、`integration`（Testcontainers PG/Redis/Pulsar）、`image`（构建不推）、
  `deploy`（仅 `workflow_dispatch`，**只推版本化镜像**，不执行集群 `kubectl apply`）。
- 测试：pytest（`-n` 并行）+ hypothesis 属性测试（`tests/test_outbox_props.py`、`test_user_dim_props.py`）；
  事件契约完备性（`tests/test_event_contract.py`：handler 注册表 ↔ 契约登记表 ↔ routing_key 表三者互覆盖）。
- **事件契约校验（两层，缺一不可）**：
  - **broker 层**：三个命名空间开 `schemaValidationEnforced=true`（compose `deploy/pulsar/entrypoint.sh`、
    k8s `infra/pulsar.yaml` 的 init sidecar；均幂等重跑 + 回读确认，不只信命令退出码）。**其确切语义经
    真机实测界定（2026-09-30，standalone 3.3.0）**：只保证「**topic 已有 schema 时，未声明 schema 的
    producer 接不进来**」（`IncompatibleSchema`）；**不校验 payload**——违约 payload（`fn` 为整数 /
    `args` 为字符串 / 整条不成形）与未声明的 `fn` 一律照发成功，把 `fn` 收紧成 Avro `enum` 亦然，
    消费者不带 schema 也不受影响；topic 尚无 schema 时，无 schema 的 producer 反而能抢先建出无
    schema 的 topic。即它管「谁在发」，**管不了「发的是什么」**——只开这个开关就是一句虚假保证。
  - **应用层**（唯一能真正强制的一层）：`app/core/event_contract.py` 的 `EVENT_CONTRACTS` 按
    「`fn` → 实参形状（线上 JSON 形态）+ 允许承载它的 routing_key」声明，三处校验：**装配期**
    （`register_task`/`register_cron_job` 校验 handler 形参元数与订阅承载能力，写错在进程启动时即炸）、
    **发布期**（`messaging.publish` 全仓唯一咽喉：违约不发、计 `event_contract_violations_total{fn,side}`
    并写 ERROR 日志；`permanent_failure_reason` 同步判为永久失败，relay 一次折叠进 `event_failures`
    而非重试 5 次）、**消费期**（`worker._on_payload` 违约 ack 丢弃）。
    判据取**线上形态**而非 Python 标注（`uuid.UUID` 过 JSON 即 str）；handler 侧只校验**元数**——
    同一 `fn` 的多个 handler（如 `apply_point_event` 四订阅扇出）形参名本就不一致，dispatch 是
    `handler(*args)` 按位置展开。告警见 `deploy/prometheus/rules/lkm-event-contract.yml`。

## 十、明确不采纳 / 已废止口径

| 项 | 结论 |
|----|------|
| L1 = aiocache | **已废止**——自实现有界 TTL+LRU |
| DataLoader（strawberry） | **不采纳**——service 层预批量已消 N+1，再叠 loader 是净负收益 |
| Celery / arq / loguru / Debezium / gRPC / RocketMQ / NATS | **不采纳**（已确认未引入） |
| topic 重命名 | **不做**——破坏已投产 topic 与在途消息，无迁移通道 |
| articles/blog **物理表**合并进 `content_items` | **不做**（目录已合并；表合并无迁移路径） |

## 十一、里程碑定义（M0–M5）

- **M0 基础稳定（不动架构）**：生产切 PG(+Timescale 扩展)、Testcontainers（PG/Redis/Pulsar）、
  统一错误码 + 全局 handler、配置收口、APScheduler 生命周期绑定。
- **M0.5 指标前移**：`prometheus-fastapi-instrumentator` + `/metrics` + 业务指标 + Grafana 面板。
- **M1 一致性补强**：`outbox_events`（hypertable）+ relay 领导者选举 + 消费者幂等 + 失败收口。
- **M2 模块内聚**：内容域聚合根（含 Like）、`follow+timeline` 合成信息流域、共享基础设施抽取 + import-linter。
- **M3 AUTH 独立服务**：独立库/独立进程 + 跨 AUTH 读模型（`user:snap` + `user_dim`）+ 启动就绪三探针契约。
- **M4 Pulsar `lkm/biz` 业务域**：按 §6.5.4 判据把业务 topic 落 Pulsar biz。
- **M5 容量与治理**：APISIX / Infisical / OTel→SigNoz / ClickHouse / 双级缓存 / msgspec / hypothesis / Prefect / k8s。
- **M6 补全轨**：对蓝图的逐章缺口补齐（P0 安全运维 / P1 一致性接口 / P2 业务功能 / P3 判据式），
  详见《执行路线图》第 9 章。
