## 推荐阅读路径

- **第一次参与后端开发**：先读《后端架构与现状》§1–§5，再读根仓库
  [DEVELOPMENT.md](../DEVELOPMENT.md) 的本地启动章节。
- **准备部署或排障**：先读根仓库 [DEPLOYMENT.md](../DEPLOYMENT.md)，再按《后端架构与现状》
  §7 核对可观测性、事件契约与探针。
- **规划一期功能**：先读《社区需求与开发规划》§2 状态总览，再进入对应业务域查看“下一步需求”
  与验收条件。
- **跨项目改动**：同时检查根仓库 [AGENTS.md](../AGENTS.md)、
  [LKM-official-website/AGENTS.md](../LKM-official-website/AGENTS.md) 与
  [LKM-service/AGENTS.md](../LKM-service/AGENTS.md)。

## 维护约定

1. **代码优先**：实现与文档冲突时，先以代码、迁移、测试和部署配置为准，再更新文档。
2. **写状态而不是口号**：用“已实现 / 部分完成 / 未实现”描述现状，并给出可验证的验收口径。
3. **不复制操作手册**：环境变量、启动命令和部署步骤以 `DEVELOPMENT.md`、`DEPLOYMENT.md` 和
   各子项目 README 为单一来源，本文档只链接，不重复维护。
4. **控制文档层级**：一个主题只保留一个主文档；历史规划与路线图在合并进现状文档后不再并行维护。
5. **提交前更新日期**：涉及架构事实或需求状态的改动，应同步更新文档开头的核对日期。
