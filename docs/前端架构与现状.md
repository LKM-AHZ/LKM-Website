# LKM 前端架构与代码实况

> **文档定位**：说明 `LKM-official-website/` 的运行时架构、路由与业务域、数据访问方式、
> 认证状态、构建链路和维护边界。本文以该子仓库的源码和配置为准。
>
> **结构与入口核对日期**：2026-10-31。项目默认**不绑定域名**：`PUBLIC_SITE_URL` 留空时使用相对
> canonical/OG URL，且不生成 sitemap。

## 1. 技术栈与定位

`LKM-official-website` 是 LKM 社区与动态官网的主前端，采用 **Astro SSR + Vue 3 + React 局部岛**
的混合架构：

| 层级             | 选型                                                     | 用途                                          |
| ---------------- | -------------------------------------------------------- | --------------------------------------------- |
| 页面与服务端渲染 | Astro 7，`output: "server"`，`@astrojs/node`             | 文件路由、SSR 数据注入、页面布局              |
| 主交互框架       | Vue 3 + Pinia                                            | Shell、论坛、文件库、StarHope、树洞等交互页面 |
| 局部编辑器       | React 19 + Tiptap 3                                      | 后台文档编辑器、CodeMirror、KaTeX、DOCX 导出  |
| 样式             | Tailwind CSS v4 + 全局 CSS                               | 主题令牌、响应式布局、Markdown 样式           |
| 数据层           | 原生 `fetch` + `Result<T, AppError>`                     | SSR/CSR 共用，统一错误语义                    |
| GraphQL          | urql + `@urql/core`                                      | `/graphql/v1` 只读聚合查询                    |
| 状态与缓存       | Pinia、浏览器存储、Dexie（编辑器）                       | 认证会话、UI 状态、本地文档与图片             |
| 测试与门禁       | Vitest、Astro Check、ESLint、Prettier、jscpd、Playwright | 单元、类型、格式、重复度与 E2E                |

## 2. 运行时拓扑

```text
浏览器
  ├─ 页面请求 ───────────────→ Astro SSR (4321)
  │                               ├─ 页面 frontmatter 通过 API_URL 直连后端
  │                               └─ HTML / Vue 水合
  ├─ /api/*、/graphql/vN ───→ Astro middleware ──→ API_URL 后端
  └─ 上传登记 WebSocket ────→ /api/v1/ws/events
```

关键事实：

- 浏览器端 REST 使用**同源** `/api/*`，不跨域；Astro middleware 负责反向代理和后端错误映射。
- SSR 数据请求使用 `process.env.API_URL` 直连真实后端；`API_URL` 未配置时前端不请求后端。
- 代理会保留 Cookie、Authorization、`X-Real-IP` 等必要请求头，并单独转发多条 `Set-Cookie`。
- GraphQL 只接受版本化端点 `/graphql/v1`；客户端在 SSR 下直连 `API_URL`，CSR 下走同源代理。

## 3. 目录结构

```text
src/
├── pages/            # Astro 文件路由（首页、论坛、文件、项目、问答、后台、树洞等）
├── layouts/          # BaseLayout / BlogLayout / SidebarLayout / MarkdownLayout
├── components/       # 跨业务通用 primitives / patterns
├── features/         # 领域功能包：auth、forum、file-library、editor、starhope、anonymous-letter 等
├── lib/
│   ├── api/          # REST/GraphQL 客户端与模块化 API
│   ├── http/         # fetch 封装、认证刷新、分页、MFA step-up
│   ├── config/       # virtual:config 解析与站点配置
│   ├── i18n/         # 服务端全量词库与客户端裁剪词库
│   ├── ws/           # WebSocket 上传登记事件
│   └── utils/        # 路径、图片、日期、Markdown、URL 安全
├── stores/           # Pinia：auth、adminAuth
├── middleware.ts     # /api、/graphql/vN 反向代理与 SSR 请求上下文
└── data/config.yaml  # 品牌、站点、SEO、博客导航等静态配置
```

## 4. 数据访问层

### 4.1 REST

- 所有模块 API 位于 `src/lib/api/modules/`，统一返回 `Result<T, AppError>`，消费方不写裸 fetch。
- `src/lib/http/client.ts` 负责：
  - SSR/CSR 自动选择后端地址；
  - Bearer token 注入；
  - 401 单飞刷新并重放一次；
  - `MFA_REQUIRED` step-up 识别；
  - 权限拒绝事件与超时/网络错误归一。
- 认证 token 的默认持久化键为 `lkm-auth-store`，HTTP 层通过适配器与 Pinia 认证 store 同步。

### 4.2 GraphQL

- `src/lib/api/graphql/client.ts` 创建 urql 客户端。
- SSR 不带 `cacheExchange`，避免模块级缓存跨请求串数据；CSR 保留缓存。
- `authExchange` 自动附加 Bearer 头，`errorExchange` 统一处理错误与登录失效。
- GraphQL 仅用于只读聚合；写操作继续走 REST。

### 4.3 SSR 请求上下文

`src/lib/ssr-context.node.ts` 用 `AsyncLocalStorage` 保存当前请求头，`src/lib/ssr-context.ts`
提供浏览器安全接口。这样 B 类认证页面在服务端渲染时可以转发 Cookie，识别当前登录用户。

## 5. 认证与用户状态

- `src/stores/auth.ts` 是前台认证的单一状态源，维护 `user`、`session`、access/refresh token、
  onboarding 状态和 2FA 临时 token。
- `src/lib/api/modules/auth.ts` 对接 `/api/v1/auth/*`，包含密码、验证码、魔法链接、OAuth、
  Passkey、注册准入、2FA、恢复码等流程。
- `src/lib/http/client.ts` 的 401 刷新队列保证并发请求只触发一次 refresh。
- 后台使用独立 `src/stores/adminAuth.ts`；管理员危险操作按后端 `MFA_REQUIRED` 进入 step-up 流程。
- 前端不自行签发或校验 JWT，只消费后端签发的令牌。

## 7. 编辑器与本地数据

编辑器是前端中 React 依赖最重的区域：

- Tiptap 提供富文本与 Markdown/MDX 双向编辑能力。
- CodeMirror 仅用于源码模式，按需加载。
- KaTeX、DOCX 导出等能力通过动态 import 保持懒加载。
- 图片与草稿通过 Dexie/IndexedDB 和编辑器持久化层保存；发布时再调用后端 API。
- `scripts/generate-icons.mjs` 在构建期按 Vue/React 分流图标，避免运行时访问 Iconify API。

## 8. 国际化与静态资源

- SSR 使用 `zh_CN.flat.ts` / `en.flat.ts` 全量词典；客户端只加载由 `generate-i18n-flat.mjs`
  裁剪出的 `*.client.flat.ts`。
- locale 由 `lkm-locale` Cookie 决定，客户端切换时同步 Cookie、Pinia/事件和页面文案。
- 图标由构建期收集的本地 JSON bundle 提供，禁止运行时 Iconify 网络请求。
- `BaseLayout.astro` 统一注入 favicon、preconnect、Sentry（配置 DSN 时）与全局样式。

## 9. 构建、配置与部署

| 变量/命令           | 作用                                                             |
| ------------------- | ---------------------------------------------------------------- |
| `API_URL`           | SSR 直连与中间件代理目标；留空则不请求后端                       |
| `PUBLIC_SITE_URL`   | 可选；稳定域名下生成绝对 canonical/OG 和 sitemap，留空不绑定域名 |
| `PUBLIC_BASE_PATH`  | 可选；子路径部署前缀，默认 `/`                                   |
| `AI_ALLOWED_HOSTS`  | 编辑器 AI 服务端代理允许访问的 HTTPS 主机白名单                  |
| `PUBLIC_SENTRY_DSN` | 可选 RUM/错误监测 DSN                                            |
| `pnpm build`        | 生成图标/词典、Astro 构建、预压缩                                |
| `pnpm check`        | Astro Check + ESLint + Prettier + jscpd                          |
| `pnpm test`         | Vitest 单元测试                                                  |

构建产物是 Node standalone 服务，默认监听 `4321`。Docker 镜像只负责运行前端；公网入口、TLS
和 `/api`、`/graphql` 的最终路由由根仓库的 APISIX/部署配置决定。

目录放置、源码/生成产物与测试位置见 [前端结构说明](../LKM-official-website/README2.md#架构)。
Shell 通用导出由 `features/shell/index.ts` 维护，站点入口直接重导出；官网入口额外暴露
`ShellSiteNavbar`，无需重复列举共享组件。
树洞本地数据层位于 `features/anonymous-letter/stores/storage/`，入口 `index.ts` 保持原有
导入接口；类型、存储及备份、加密、个人数据、偏好与历史内容分别归入对应模块。
共享内容由 `stores/api.ts` 对接后端，本地 `content.ts` 仅用于兼容历史数据。

## 10. 维护边界

- 前端不保存后端业务真相；所有写操作必须经后端校验与权限判定。
- 不在客户端存长期敏感凭证；页面权限只是 UX，服务端仍必须独立鉴权。
- 直接调用 REST/GraphQL 时优先使用 `src/lib/api`，不要在组件里散落 fetch。
- 修改路由、请求/响应 schema 或 GraphQL 字段后，同步更新 TypeScript 类型和相关测试。
- 本项目不默认绑定域名；新增 absolute URL 时必须提供无域名时的相对路径回退。
