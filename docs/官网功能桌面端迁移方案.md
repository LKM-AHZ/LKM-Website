# 官网功能桌面端迁移方案

> 目标：把 `LKM-official-website` 的用户可见功能逐块对齐到 `LKM-desktop`。
> 口径：**功能一致即可，不要求实现、交互、视觉一致**；纯 mock / 空模块 / 静态演示不迁。
> 盘点基线：website `1cd17ab`（2026-11-07）、desktop `dbd534c4`（2026-11-11，P0–P3-5 已完成）。
> 后端契约细节仍以 `docs/桌面端接入后端方案.md` §7 为准，本文只写功能差距与落地顺序。

## 2. 迁移批次

批次按依赖排序，每批独立可验收；批内不要求一次做完。

### W1 认证与账户闭环（基础）

| 功能点 | 做法 | 端点 |
| --- | --- | --- |
| 注册补齐 | 用户名+密码 + 邮箱/手机验证码；local 注册；准入待审态页面 | `POST /auth/reg/normal`、`/auth/reg/normal/verify`、`/auth/reg/local`、`/auth/reg/email|phone(+verify)` |
| onboarding | 4 步（身份标签/推荐关注/答题/新人任务），可逐步保存、可跳过 | `GET /auth/onboarding`、`PUT /auth/onboarding/steps/{1-4}`、`POST /auth/onboarding/skip` |
| 找回密码 | 邮箱/手机/Magic Link 发码 → 验证 → 设新密码；已开 2FA 时补 TOTP | `/auth/recover/{check,email,phone,magic-link}*`、`/auth/recover/verify-totp`、`/auth/recover/complete` |
| 2FA | 登录后强制 setup（扫码+恢复码）；账户页开关；危险操作 step-up 复用现有弹窗 | `/auth/2fa/verify`、`/auth/2fa/setup/{begin,complete,temp,complete/temp,confirm}` |
| Passkey 管理 | LKM 版凭据列表/新增/删除（删除需 step-up），替换 Solian 的 `settings_auth_factors` | `/auth/passkey/credentials`、登录 begin/complete 已有 |
| GitHub OAuth / Magic Link | 系统浏览器打开授权页，回跳走本地回环监听或自定义 scheme，解析 token fragment | `/auth/oauth/github/login`、`/auth/login/magic-link/request|verify` |
| 账户设置 | 资料编辑、头像上传、绑定/解绑邮箱/手机/GitHub | `PUT /auth/{id}/profile`、`POST /auth/avatar`、`/auth/settings*`、`bind-email|bind-phone` |
| 我的内容 | 我的提问/帖子/项目及申请、收藏、历史 | `content/qa/questions`(author)、GraphQL `ContentItems`(author_id)、`/projects`、`/projects/applications/me`、`/interaction/me/favorites`、`/me/history` |

验收：新用户注册→onboarding→资料→绑定；找回密码；2FA 开关；我的提问/收藏/历史可见。

### W2 文件库与编辑器

| 功能点 | 做法 | 端点 |
| --- | --- | --- |
| 文件库列表 | 分页、目录下钻、类型/状态/下载量筛选、搜索、列表/卡片切换 | `GET /files`、`GET /search?content_type=library_file` |
| 文件详情 | 元数据、版本列表、下载、预览（均需 Bearer） | `GET /files/{id}`、`/versions`、`/download/url`、`/content`、`/preview` |

| 编辑器 | Markdown 源码 + 预览 + 图片上传 + 自动保存 + 发布到专栏/博客 series；Tiptap/CodeMirror 能力不照搬 | GraphQL `BlogSeriesDetail`、`BlogFileContent`；`PUT /blog/series/{id}/files/{path}`、`POST /blog/series/{id}/publish` |

| 批注/导入导出/AI | 不迁（§5 决策 1） | — |
| 后台文档入口 | 文档列表用本地存储（prefs/Drift）等价 localStorage，跳编辑器 | 无 API |

验收：上传→审核中→通过→在文件库可见可下载；编辑器能新建、保存、发布并回读。

## 4. 批次依赖与顺序

```
W1 认证/账户 ──► W2 文件库/编辑器 ──► W5 后台（文档、用户）
      │                │
      └──► W3 社区 ────┴──► W4 特色域 ──► W6 StarHope ──► W7 首页
```

- W1 是一切写操作与个人页的前提。
- W2 的文件库详情是 W3 搜索文件 Tab 的目标页。
- W6 独立，可与其他批并行；W7 依赖 W1（个人数据）与 W4（问答/项目数据）。

## 6. 实施约定

- 命名：不为迁移新增 `lkm` 前缀/后缀，沿用现有领域命名。
- 路由：新增 tab 同时改 `lib/route.dart`、`lib/misc/tabs_screen.dart`、`lib/tab_destinations.dart` 三处；`route.gr.dart` 本机无法 build_runner，按生成格式手补。
- i18n：只维护 `en-US` / `zh-CN` / `zh-TW` 三份，新增键三语同步。
- 测试：`export PATH="/usr/bin:$HOME/flutter/bin:$PATH"` 后跑 `flutter test --no-pub`；对照当前基线 **789 通过 / 22 失败**，不得新增失败项。
- 每个 API 层新增非平凡解析/刷新逻辑时，补一个 `test/core/*_test.dart` 用例。
- **优先复用桌面现有实现**：编辑器、表单、设置页、图片选择等已有代码直接改造使用，不另起一套（用户 2026-11-11 明确）。
- 不自动提交 git。

## 7. 主要风险

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| 编辑器范围失控 | 官网编辑器 55 个文件，含 Tiptap/CodeMirror/版本/批注/导入导出 | 按 §5 决策 1 锁定首版范围，剩余能力列后续 |
| OAuth/回跳在桌面三平台不一致 | Windows/macOS/Linux 的 scheme/回环行为不同 | 先用回环监听，打包期逐平台验证 |
| Bot 面板依赖 Web 形态 | BFF + iframe + SSO + SSE，Flutter 复刻成本高 | 按 §5 决策 3 选外开或精简原生 |
| StarHope 数据模型迁移 | IndexedDB → Drift，需定义同步冲突规则 | 只做 last-write-wins + 游标；先单设备验收 |
| 与 Solian 域并存造成入口重复 | 桌面上 posts/drive/chat 等 Solian 入口与 LKM 新页面职责重叠 | 迁移期在设置里分组；对齐完成后再议旧入口去留（P4 已暂缓） |
| 契约漂移 | 官网请求以当前实现为准，后端可能有未落 openapi 的字段 | 动手前对照 `tests/contracts/openapi.json` 与实测响应 |
