# 理科迷社区需求与开发规划（一期）

> 核对日期：2026-11-28。依据根仓库固定的 LKM-desktop 与 LKM-service 提交核对。
> “已有代码”表示页面、接口或处理逻辑存在；目标环境的部署、权限和完整用户流程仍需验收。
> LKM 与客户端保留的 Solar 服务使用独立地址，不能把 Solar 功能表直接当作 LKM 交付清单。

## 1. 定位与目标

一期主线是“找到内容—发布内容—获得回应—沉淀成果”：
浏览板块、发帖求助、评论互动、
查找资料、参与项目与考试。当前客户端为 Flutter 桌面端；
旧网页客户端的页面和示例数据不再作为实现状态的依据。

## 2. 代码现状总览

| 业务域 | 后端已有能力 | 桌面接入与后续重点 |
|---|---|---|
| 发现与搜索 | 信息流、帖子/专栏/公开文件检索 | 已有 API 客户端与社区入口；验收筛选、跳转、权限及空状态 |
| 论坛与专栏 | 板块、内容、评论、专栏申请/审核/发布、订阅与单帖 watch | 发帖、专栏列表/文章/申请已有接入；核对管理与订阅界面覆盖 |
| 悬赏求助 | 积分托管、回答、采纳、关闭与到期退款 | 验收资金守恒、并发采纳及退款竞争 |
| 项目协作 | 孵化、项目编辑、更新、成员角色、邀请、加入申请 | 当前 ProjectsApi 覆盖展示与孵化申请；补齐协作写操作接入 |

## 3. 主页与全站发现

桌面社区卡片、发现页和 API 客户端已接入 LKM 数据，考试入口指向 `/exam`。
不再维护旧首页的竞赛倒计时、每日题目或网页题库 mock 清单。

- **P0**：核对每个入口使用的服务地址、登录态和真实数据，错误不能静默显示成空列表。
- **P1**：统一帖子、专栏、文件的筛选和详情跳转；题库检索按实际接口覆盖推进。
- **P2**：在真实内容和权限稳定后增加运营推荐与排序反馈。

验收：结果可打开对应详情；未授权内容不出现在列表和搜索中；无数据与请求失败可区分。

## 4. 论坛发帖与专栏

桌面 `compose_post.dart` 通过 `ContentApi.createDiscussion` 发布内容，
`ColumnsApi` 已提供专栏、文章与申请调用。后端已有目标订阅和单帖 watch，
不能继续将“标签/专栏订阅”整体列为未实现。

- **P0**：验收现有编辑器到服务端存储、再到详情渲染的公式、代码块和图片链路。
- **P1**：核对专栏申请、审核状态、发布和管理界面；补齐尚未接入的订阅入口。
- **P1**：验证取消订阅、通知偏好、屏蔽关系与自动 watch 的组合行为。
- **P2**：按运营需要扩展连载、定时发布和导出。

验收：内容保存和重开后格式一致；审核与属主权限生效；订阅只向符合条件的用户通知。

## 5. 悬赏求助

后端已有发布扣减托管、回答、采纳派发、关闭和到期退回。业务托管额度不能等同于
独立的冻结余额账户；余额、流水和业务状态应一起核对。

- **P0**：验证重复/并发采纳、到期与采纳竞争、关闭退款和降权后的操作。
- **P1**：明确违规、申诉、通知与加急展示规则。
- **P2**：在资金闭环稳定后扩展反作弊策略。

验收：派发与退款合计不超过原始悬赏；禁止自采纳；每条结束路径有可追溯流水。

## 6. 项目广场与招募协作

后端 `projects/router.py` 已有项目编辑、进展追加、成员角色调整、邀请接受/拒绝、
加入申请及审核接口；孵化申请与加入申请分别建模。
桌面 `ProjectsApi` 当前主要覆盖广场、详情、我的孵化申请和申请提交。

- **P0**：在桌面接入项目更新、成员/邀请和加入申请，按服务端权限显示操作。
- **P0**：验收重复申请、邀请过期、角色降级及移除成员后的文件访问。
- **P1**：明确招募截止、满员、结项和进展历史的展示规则。
- **P2**：按需求扩展里程碑和停滞提醒。

验收：用户可申请加入具体项目并查询结果；项目更新可追溯；无权限用户无法修改或审核。

## 7. 文件库

后端已有同步/直传上传、审核、密级、项目关联、编号、版本历史、预览和公开检索。
Office 转换、文本提取、病毒扫描和备份依赖目标环境，需分别验收。

- **P0**：覆盖公开/内部/机密、项目成员、审核前后和历史版本的列表/搜索/预览/下载权限。
- **P0**：验证扫描失败、转换失败和存储不可用的错误反馈，完成备份恢复演练。
- **P1**：完善编号、正文搜索、版本对比或恢复体验。
- **P2**：严格分类编码及多人在线编辑需单独评估并制定迁移方案。

验收：直接 URL 不能绕过可见性；新版本不覆盖旧版；转换失败有明确提示。

## 8. 竞赛、考试与题库

后端已具备题库组、报名、资格前置条件、练习、错题记录、可分享 trial、
人工阅卷和赛题发布到练习库。桌面 `ExamApi` 与考试页面已接真实列表、详情、
开始作答、提交、证书和榜单；报名、练习等扩展调用尚需补齐。

- **P0**：接入报名/取消、资格提示、练习入口和错题记录，明确个人赛规则。
- **P0**：验收服务端判分、人工阅卷、时间窗、重复提交和题目发布审核。
- **P1**：完善断线续答与争议题流程；组队、实时榜单按赛事规则另行验收。
- **P2**：实时 PK、段位和个性化推荐。

验收：真实用户可完成报名、答题、提交与结果查看；答案不提前泄露；题目经审核才进入练习。

## 9. 聊天室与协作通讯

聊天采用 Tinode，LKM AUTH 提供账号桥，APISIX 转发 `/v0/*`。
桌面接入位于 `lib/chat/tinode/`；LKM `/api/v1/ws/events` 继续负责上传和通知推送，
两条协议分别维护，见 [实时协议](./实时协议.md)。

- **P0**：联调登录、房间权限、消息持久化、历史补拉与断线重连。
- **P0**：验收举报、撤回、聊天封禁与用户屏蔽；确认已连接会话的封禁生效窗口。
- **P1**：验证附件、公式/代码和内容卡片，避免绕过文件权限。
- **P2**：聊天转帖、项目/竞赛自动建群、语音视频按实际场景扩展。

验收：消息只对有权限成员可见；重连可补回已提交消息；处置结果可追溯。

## 10. 拾光树洞与用户关系

树洞后端仍有匿名身份、私密信件和匿名对话模型。当前桌面仓库不能沿用
旧网页“已接通全部页面”的结论。普通用户 block/mute 与好友关系已有后端实现，
匿名树洞的隔离规则需独立验证。

- **P0**：确定树洞是否纳入本期桌面范围；纳入时补齐入口、匿名身份保存和恢复流程。
- **P0**：覆盖公开、自见、随机投递及封存内容的权限，核对举报、限流和撤回。
- **P1**：逐面验证 block/mute 对信息流、搜索、通知、互动及聊天的影响。

验收：无法访问他人的私密内容；会话失效有明确提示；屏蔽规则在各入口一致。

## 11. 一期交付顺序

1. 验收已有路径：认证、内容、悬赏资金、文件权限、考试提交及 Tinode 账号桥。
2. 补齐桌面对项目协作、专栏管理、考试报名/练习的接入，完成权限与异常流程。
3. 明确树洞、组队比赛和高级聊天的交付范围，再安排运营增强。

接口实现以 `LKM-service/app/modules/` 和 `auth/` 为准；桌面接入以
`LKM-desktop/lib/core/api/`、业务页面和测试为准。功能存在与上线验收分别记录。
